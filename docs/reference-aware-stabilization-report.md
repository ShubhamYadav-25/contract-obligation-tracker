# Reference-Aware Extraction Stabilization Report

Date: 2026-07-24

## Scope

This pass stabilized the completed reference-aware obligation extraction integration. It did not add new extraction stages, database migrations, scheduler changes, state-machine changes, parsing changes, OCR changes, storage changes, or persistence repository changes.

## Provider Selection

Runtime selection is implemented in `apps/api/src/bootstrap/register-workers.ts` through exported `createObligationExtractor(...)`.

`OBLIGATION_EXTRACTOR_MODE` is parsed in `apps/api/src/config/env.ts` with these values:

- `auto`
- `heuristic`
- `groq`
- `reference-aware-gemini`

Default is `auto`.

Selection rules:

- `auto` uses `GroqObligationExtractionProvider` when `GROQ_API_KEY` is configured.
- `auto` uses `HeuristicObligationExtractionProvider` when `GROQ_API_KEY` is absent.
- `heuristic` always uses `HeuristicObligationExtractionProvider`, even when a Groq key exists.
- `groq` requires `GROQ_API_KEY` and uses `GroqObligationExtractionProvider`.
- `reference-aware-gemini` requires `GEMINI_API_KEY` and `GEMINI_MODEL` and uses `ReferenceAwareObligationExtractor`.
- Explicit `groq` and `reference-aware-gemini` modes fail configuration validation when their required keys are missing.
- Reference-aware Gemini failures do not silently downgrade to Groq or heuristics.

## Source Anchoring Invariants

Verified deterministic source anchoring remains implemented in `apps/api/src/modules/extraction/reference-aware/source-index.ts`.

Key invariants:

- `ContractSourceIndex` is indexed by internal global line number.
- Page number is preserved on every `ContractSourceLine`.
- Page-local line number is preserved when supplied, otherwise represented as `null`.
- `originalText` and normalized source text are stored separately.
- `normalizeSourceLineText(...)` collapses extraction-only whitespace without changing line numbers.
- Duplicate and missing global lines are reported through `ContractSourceIndex.diagnostics`.
- `resolveEvidenceSpan(startLine, endLine)` rejects invalid boundaries, missing boundaries, missing middle lines, and reversed spans.
- Page numbers and exact quotes are derived from `ContractSourceIndex`, not from model output.
- OCR-produced pages are supported through `ParsedDocumentPage.extractionMethod` values and `ContractSourceIndex.fromParsedPages(...)`.

## Candidate And Evidence Safety

Window-level extraction remains implemented in `apps/api/src/modules/extraction/reference-aware/obligation-candidate-extractor.ts`.

Stabilized behavior:

- Candidate IDs are stable across model candidate order.
- Candidate IDs are stable across evidence span order.
- Candidate IDs include semantic obligation fields and sorted evidence spans.
- Different obligation objects produce different candidate keys.
- A single raw evidence span crossing pages is rejected; cross-page support must use multiple page-local spans.
- Definitions, rights-only clauses, excluded boilerplate, invalid evidence, unresolved actors, and unavailable core cross-references remain review or rejection cases according to existing deterministic rules.

## Verification, Deduplication, Consolidation, And Review Gate

Source verification and post-processing remain implemented in `apps/api/src/modules/extraction/reference-aware/obligation-source-verification.ts`.

Stabilized behavior:

- Model-provided quote text is ignored and exact quotes are reconstructed from the source index.
- Evidence outside the supplied candidate window is rejected.
- Missing middle lines reject a source span.
- `ACTION` evidence is required.
- `ACTOR` evidence or a valid contextual party-resolution method is required.
- Exact duplicates from overlapping windows are deduplicated with stable deterministic keys.
- Adjacent actor/action and timing fragments can consolidate when responsible party, counterparty, normalized action, object, section path, and evidence adjacency match.
- Similar duties in separate sections do not consolidate.
- Same actor and frequency with different obligation objects do not consolidate.
- Duplicate evidence spans are sorted and removed during verification/consolidation.
- Consolidation is idempotent.

## Metadata And Metrics

Reference-aware orchestration remains implemented in `apps/api/src/modules/extraction/reference-aware/reference-aware-obligation-extractor.ts`.

Stabilized behavior:

- Review metadata stores compact `sourceReferences` with page-local and global line ranges.
- Duplicate review source references are removed.
- Review metadata is JSON-safe.
- Review metadata does not contain API keys, complete prompts, or complete contract bodies.
- Metrics include candidate windows, raw candidates, confirmed, review required, rejected, duplicate removals, consolidations, LLM request count, retry count, and extraction duration.
- `CountingStructuredLlmClient` includes retry counts from a delegate implementing `StructuredLlmMetricsProvider`.
- `GeminiStructuredLlmClient` implements `StructuredLlmMetricsProvider` and records actual retry attempts.
